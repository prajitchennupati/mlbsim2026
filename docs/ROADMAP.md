# Roadmap

Consolidated from the 15 requested phases into 11 milestones. **`main` stays green and the
system runs at the end of every milestone.** Each milestone lists its concrete "it runs"
deliverable.

Locked decisions: GitHub Actions + cron for orchestration · Render (API) + Supabase
(Postgres) for hosting · backfill 2015+ full PA/Statcast and 2010+ games/W-L · live
in-game predictions deferred to M9.

CLI `mlbsim simulate-season --n 100000 --as-of`. **Benchmark: 100k seasons ≈ 0.65 s (167M game-sims/s); 1M ≈ 6.5 s.** Probability totals are exact (Σ p_playoffs = 12, Σ p_division = 6, Σ p_pennant = 2, Σ p_WS = 1); WS length ≈ 5.8 games, P(sweep) ≈ 0.12. **Remaining:** exact tiebreakers; fixed projected-bracket view (M8). |

| **M9 ✅ (code)** | Automation + live + MLOps | `mlbsim-pipeline/flows/`: guarded step-runner (`_run.py` — every step timed, failures logged + recorded, flow keeps going, optional Slack/Discord `alert()` + frontend `ping_revalidate()`). `run_daily` = ingest schedule + finished games + Statcast → season stats → features → Elo → [opt. retrain] → predict (`direct_v1`) → ensemble predict → **resolve outcomes** → season Monte Carlo → revalidate. `run_live` wraps `update_live_games`. `pipeline_status()` = warehouse freshness, last prediction/sim per model/scope, registry staleness, unresolved-prediction backlog. CLI `mlbsim flow daily|live|status` (JSON out, non-zero exit on any failed step). **Live win probability:** `mlbsim_engine.game.GameState` + `simulate_game(start_state=…)` resumes the PA cohort mid-game; `live_win_probability()` reads off P(home win); `mlbsim_models/pipelines/live.py` `state_from_feed()` parses a GUMBO `feed/live` linescore → `GameState`, `update_live_games()` polls the slate and writes `is_live` `game_predictions` rows under model `live_v1`. `mlbsim_models/pipelines/resolve.py`: `resolve_outcomes()` fills `serving.prediction_outcomes` (Brier / log-loss / correct) for finalised non-live predictions (idempotent), `rollup_eval()` aggregates them into a `model_eval_runs` + `calibration_bins` row. `mlbsim_models/registry.py` `log_model_run()` = optional MLflow sink, no-op unless `MLBSIM_MLFLOW_TRACKING_URI` is set (mlflow is an optional extra). Migrations 0001–0010 apply and reverse cleanly. Commit `06258aa` fixes the batch of latent ingest/serving/flow bugs that first surfaced on a real DB (schedule league/division codes, park + probable-pitcher FK stubs, JSONB server defaults, `prediction_outcomes` ON DELETE CASCADE, Poisson-μ clamp, slots-dataclass logging). **Remaining:** deploy the crons with live creds; exact per-reliever bullpen rates for live WP (still starter-rate fallback). |

## Definition of done per milestone

1. Code merged to `main`, CI green.
2. New CLI verb or endpoint works end-to-end on real data.
3. Tests (unit + at least one integration) for the new surface.
4. Relevant `docs/` section updated.
5. If a model was added: an entry in `model_versions` and a metrics row vs its baseline.
